## ARCHITECTURE

### 1. MULTI-AGENT SYSTEM (LangGraph)
Create 5 specialized agents with conversation memory:

**Agent 1: Welcoming Agent**
- Handles greetings, general queries, platform navigation
- Personality: Friendly, helpful, concise
- Routes business queries to Data Analytics Supervisor

**Agent 2: Data Analytics Supervisor**
- Creates execution plans for complex queries
- Assigns tasks to team members
- Validates all outputs from other agents
- Implements feedback loops if answers are inaccurate
- Makes final decision on response quality
- Memory: Remembers user preferences and past query patterns

**Agent 3: Data Manager**
- Expert on all database schemas across 5 domains
- Knows every table, column, KPI, and data relationship
- Provides metadata and data context to other agents
- Memory: Tracks which data sources are most relevant per domain

**Agent 4: Data Engineer**
- Converts natural language to SQL queries
- Executes data retrieval operations
- Handles data transformations and aggregations
- Memory: Optimizes repeated query patterns

**Agent 5: Analytics Expert**
- Performs statistical analysis and predictive modeling
- Generates insights, trends, and recommendations
- Creates visualization specifications for frontend
- Detects anomalies and patterns
- Memory: Builds knowledge of domain-specific analytical patterns

**Agent Communication:**
- All agents share context about current domain selection
- Agents communicate through LangGraph state management
- Real-time agent conversation log streamed to UI viewer
- Implement short-term (conversation) and long-term (user history) memory

### 2. DOMAIN DATA GENERATION
Generate realistic CSV datasets for 5 domains:

**Telecom Domain (10 tables):**
- customer_profiles, call_records, data_usage, billing, network_performance, churn_data, device_inventory, complaints, promotions, regional_coverage
- KPIs: ARPU, churn rate, network uptime, data consumption, customer satisfaction

**Banking Domain (10 tables):**
- accounts, transactions, loans, credit_cards, customers, branches, atm_usage, fraud_alerts, investments, customer_service_logs
- KPIs: Transaction volume, loan default rate, customer acquisition cost, NPS, fraud detection rate

**Digital Marketing Domain (10 tables):**
- campaigns, ad_performance, website_traffic, conversions, email_metrics, social_media, seo_rankings, customer_journey, ab_tests, budgets
- KPIs: CTR, conversion rate, CAC, ROAS, engagement rate, bounce rate

**Healthcare Domain (10 tables):**
- patients, appointments, medical_records, prescriptions, lab_results, staff, departments, billing, insurance_claims, equipment
- KPIs: Patient wait time, bed occupancy, readmission rate, treatment outcomes, staff utilization

**FMCG Domain (10 tables):**
- products, inventory, sales, distributors, retailers, promotions, supply_chain, market_research, customer_feedback, pricing
- KPIs: Sales velocity, inventory turnover, market share, distribution coverage, profit margin

Each table should have:
- 500-2000 rows of realistic data
- Proper relationships (foreign keys)
- Timestamps for time-series analysis
- Mix of numerical and categorical data
